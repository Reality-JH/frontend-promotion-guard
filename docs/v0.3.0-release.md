# Frontend Promotion Guard v0.3.0

Version 0.3.0 makes the gate boundary explicit. FPG is not a mandatory deployment step after every frontend edit: targeted work should use the project's focused tests, related batches may use `verify` against an already running target, and only an explicit release should use `promote`.

The GitHub Action now requires `confirm-promotion: true` in addition to `command: promote`. This prevents ordinary pull-request and feature workflows from mutating container state through an accidental command change. CLI users still opt into promotion explicitly with `fpg promote`.

All v0.2.0 safeguards remain in place, including runtime configuration validation, immutable image evidence, verified rollback, release locking, baseline manifests, credential redaction, and Docker integration scenarios that assert the final production image ID.
