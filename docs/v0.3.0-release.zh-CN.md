# Frontend Promotion Guard v0.3.0

v0.3.0 明确了门禁边界。FPG 不是每次前端改动后的强制部署步骤：单项开发应优先使用项目自身的定向测试，相关事项成批收口时可以对运行中的目标执行 `verify`，只有明确发布时才执行 `promote`。

GitHub Action 现在要求在 `command: promote` 之外同时设置 `confirm-promotion: true`。这样可以防止普通 Pull Request 或功能开发工作流因命令误改而改变容器状态。CLI 用户仍通过显式执行 `fpg promote` 进入发布流程。

v0.2.0 的安全机制全部保留，包括运行时配置校验、不可变镜像证据、回退复验、发布锁、基线清单、凭据脱敏，以及核对最终正式镜像 ID 的 Docker 集成场景。
